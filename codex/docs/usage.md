# 当前对话先制定计划，再开始执行

在需要执行工作的那个 Codex 对话使用 ProgressTarget。每个对话有自己的计划，即使它们打开的是同一项目目录。恢复原对话会恢复原计划；新对话和分叉对话默认为空。

插件更新后若旧对话仍只有旧参数或看不到工具，先重新加载客户端，再回到这个对话检查插件是否已加载。这个安装刷新步骤不代表日常每份计划都要另开 Codex 任务。

## 制作新计划

把【X任务】替换为实际目标。优先从当前已安装的技能定位指南，无须手动复制本机开发目录。`../../GUIDE.md` 相对技能的 `SKILL.md` 所在目录解析，不是相对任务工作目录。若技能目录因更新而失效，先查找当前实际安装的 progress-target 技能，再读取指南。

```text
请用 ProgressTarget 为【X任务】制定当前 Codex 对话自己的 v2 计划，暂不执行。
先使用已安装的 progress-target:progress-target 技能，完整阅读其 SKILL.md，并按其中的相对链接定位和完整阅读 GUIDE.md。不要沿用其他对话中的开发路径或旧版本缓存路径。
从当前对话的可信上下文或当前任务 shell 读取真实 CODEX_THREAD_ID，每次工具调用都传该 threadId；不要使用目录、进程号、根 sessionId 或其他对话的计划。先 plan_get 检查本对话；没有计划再 plan_create，已有未收尾计划则按现有计划处理，不能静默覆盖。
所有时间使用北京时间 +08:00。遵循第一性原理和最小充分原则：无必要不增阶段、指标、交付物、证据、资源分支或审计；SHA、复现说明、manifest、额外报告和消融均非默认要求。
按真实依赖拆阶段，充分阅读必要资料，选择与最终目标相关、有测量方法和阈值依据且非空洞“>0”的质量指标，填写 finalObjective、metricResearch、objectiveContribution、deadlineAt、必要交付物和 executionPlan。未实测值填 null，资源发现标记 deferred，执行前再真实查询，不伪造结果。
计划 executionState 保持 paused，全部阶段 pending。不启动任务命令、实验、后台作业或资源查询，不占用资源。完成后给我计划摘要和本对话的看板链接，等待我明确开始执行。
```

插件已加载并读过指南后，也可简写为：“用 ProgressTarget 制作【X任务】的新计划，放在当前对话，暂不执行。” Skill 会展开上述流程。

## 修改现有计划

```text
请修改当前 Codex 对话自己的 ProgressTarget 计划，暂不执行。修改要求：【具体改动】。
先使用已安装的 progress-target:progress-target 技能，完整阅读其 SKILL.md 及相对链接指向的 GUIDE.md；若缓存路径已失效，先定位当前安装版本。从当前任务读取真实 CODEX_THREAD_ID，以该 threadId 调用 plan_get(detail=true)，并携带最新 expectedRevision 更新；没有当前计划就说明，不选择其他对话的计划。
使用 plan_manage 的 revise-plan 更新尚未开始部分。保留未获授权删除的历史阶段；进行中和已结束阶段由插件保留，不回退为 pending。不通过更改最终目标或降低已启动阈值使历史达标。只有本请求或已有会话明确授权删除时，才删除指定阶段或计划。
按第一性原理只保留影响决策、最终质量、可用性、安全或真实下游需求的内容；精简不必要的 SHA、复现说明、manifest、额外报告、消融和重复审计。新指标须有调研、测量方法和阈值依据，不能使用空洞“>0”。不编造测量或资源状态。
所有时间使用北京时间 +08:00。修改后的阶段均保持 pending，整个计划保持 paused，不启动任务或资源查询。保存后给我修改摘要与本对话的看板链接。
```

## 开始、暂停和查看

开始执行：

```text
按当前对话的 ProgressTarget 计划开始执行。先读当前计划与最新 revision，将执行状态设为 active。逐阶段在启动前查询真实资源，提交新鲜快照和 executionPlan，再按质量、交付物和截止时间约束推进；及时记录实测结果与调整。不要为这个请求另开 Codex 对话。
```

之后可直接说：

- “查看当前对话的 ProgressTarget 计划。”返回的链接只显示本对话计划，页面自动更新。
- “暂停当前计划。”保存暂停状态；如有后台作业，按实际暂停范围处理并说明结果。
- “继续执行当前计划。”读取保存状态，从尚未完成的工作恢复。
- “当前计划收尾后，为【下一个目标】制定新计划，暂不执行。”在同一对话建立下一份，上一份保留为历史。

规划、执行和进度查看都在同一对话完成。看板的服务进程可以共用，但计划归属、当前计划指针和每次读取不会共用。

MCP 读取和看板链接不依赖自动 Hook。三个 Hook 需要另行获得宿主信任并验证；在此之前，点击中断按钮后不能依赖插件自动保存 paused；恢复对话时应明确说“暂停当前计划”，由 MCP 保存状态。需要自动恢复、续跑或中断记录时，先在宿主 Hook 管理中审阅和信任插件 Hook，再验证真实触发；插件不会替你更改信任设置。

完整迁移核对见 [功能审计](feature-audit.md)，精确契约见 [GUIDE](../plugins/progress-target/GUIDE.md)。
